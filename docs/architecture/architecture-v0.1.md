# Architecture v0.1 — PlantAssist-X 系统架构设计

> 状态：待评审

## 1. 总体结构

```
┌─────────────────────────────────────────────────────┐
│  管理员控制台                                        │
│  设备注册 · 授权策略 · 撤权 · 审计查询                │
└─────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────┐
│  企业内网授权与会话协调服务                            │
│  设备身份 · 策略判定 · 短期会话凭证 · 在线状态          │
│  （不转发屏幕视频；不依赖公网，不承担媒体中继）          │
└─────────────────────────────────────────────────────┘
        │                                   │
        ▼                                   ▼
┌─────────────────────┐         ┌─────────────────────┐
│  Win11 发起端        │  ←──→  │  Win10/11 目标端     │
│  设备认证、屏幕采集、  │  认证后  │  会话授权检查、桌面   │
│  编码、远程显示、      │  内网点  │  捕获、画面解码、     │
│  授权输入            │  对点媒体 │  输入处理、状态提示   │
└─────────────────────┘  /控制   └─────────────────────┘
```

> **重要架构决策**：纯内网直连不代表完全不需要服务端。首期设置一台企业自有的轻量协调服务，负责注册、授权和会话发现；屏幕数据尽量在两端直接传输。如需完全无服务器方案，需评估预共享信任和点对点发现，但设备撤权、凭证轮换和审计会更复杂。

## 2. 模块边界

| 模块 | 职责 | 安全要求 |
| --- | --- | --- |
| Device Registry | 设备登记与状态 | 独立凭证、撤销、轮换 |
| Policy Engine | 计算谁可以控制哪台设备 | 默认拒绝、权限最小化 |
| Session Broker | 协调会话建立 | 不授予超出策略的权限 |
| Screen Capture | 捕获获准共享的桌面或窗口 | 明确采集范围、停止后释放 |
| Media Transport | 传输屏幕帧与音视频相关元数据 | 加密、抗重放、限流 |
| Input Gateway | 处理远程鼠标键盘输入 | 逐会话授权、限制目标会话 |
| Target UI | 展示会话状态和终止入口 | 状态不可静默隐藏 |
| Audit Service | 记录安全事件 | 限制修改、保留策略、完整性校验 |

## 3. 技术栈建议

| 模块 | 建议实现 |
| --- | --- |
| Windows 客户端 | C# / .NET，WPF 或 WinUI |
| 屏幕采集 | Windows Graphics Capture 等受支持接口 |
| 视频编码 | Windows Media Foundation，按实测选择编码器 |
| 实时传输 | 内网 TCP/UDP，采用加密会话协议 |
| 设备发现 | 手动登记、IP/主机名导入；不强制依赖域控 |
| 身份与授权 | 独立设备身份、管理员授权、短期会话凭证 |
| 安全审计 | 连接、授权、开始/结束时间、异常及权限变更记录 |

## 4. 必须提前解决的 Windows 限制

- **不锁屏**：可以设计为不主动锁定目标会话，但不能保证所有 Windows 策略、屏保和断连场景都不触发锁屏。
- **用户无感**：可以做到低干扰运行，但不应隐藏控制状态。建议管理员预部署，目标端显示轻量的远程会话状态。
- **UAC 与安全桌面**：管理员提权、安全桌面及登录界面存在特殊限制，不能承诺普通桌面控制能力覆盖所有这些场景。
- **Windows 10**：需要明确目标机器是否仍在获得安全更新，并验证实际系统版本和补丁情况。
- **网络安全**：即使只有内网，也要使用强身份认证、加密传输、设备白名单和最小权限，不能只凭 IP 地址就允许控制。

## 5. 权限分离架构（关键）

Windows 服务通常运行于 Session 0，而交互桌面位于用户会话中。不能简单地把一个后台服务当成能够直接读取或操作所有用户桌面的程序。

采用权限分离架构：

- **特权尽量低的后台服务**：负责设备身份、策略和连接生命周期。
- **交互式客户端**：在当前用户会话中运行，负责画面显示、可见状态提示及受支持的桌面交互。
- **服务与用户进程之间**：采用经过身份验证的本地 IPC，并严格限制允许调用的操作。
- **不通过**注入进程、绕过安全桌面或复制用户凭据解决会话隔离问题。
