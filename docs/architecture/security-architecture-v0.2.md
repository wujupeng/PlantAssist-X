# Security Architecture v0.2 — 安全架构补充

> 状态：Gate B 补充 · 针对 DG-03 / DG-04 及三项必须补充的设计细节
>
> 本文档是对 Architecture v0.1 的安全补充，不修改 `8927b3d` 基线已有内容，仅追加明确化设计。

## 1. 补充动机

Gate A 审查（PM 意见）确认文档覆盖核心需求，但以下三项必须补充后方可批准 P0：

1. **设备身份与会话授权不能只依赖协调服务的判断结果**：目标端必须独立验证授权凭证、会话范围、有效期和撤销状态。
2. **必须定义撤权传播与失联行为**：协调服务不可用、撤权消息未送达、设备重启和网络分区时，现有会话如何停止或失效。
3. **必须区分屏幕采集权限与系统控制权限**：交互客户端最小权限；后台服务不能成为任意输入注入、任意进程操作或跨用户会话访问的通用代理。

## 2. 设备身份与凭证管理（对应 DG-03）

### 2.1 凭证生命周期

| 阶段 | 执行方 | 说明 |
| --- | --- | --- |
| 签发 | 协调服务（管理员触发） | 为每台已登记设备生成独立设备密钥对 + 设备证书，绑定设备唯一标识 |
| 分发 | 管理员预部署 | 安装时写入目标端受保护存储，不通过网络明文传递私钥 |
| 保护 | 目标端本地 | 私钥加密存储（DPAPI / CNG），仅低特权服务可读，交互客户端不可直接访问 |
| 轮换 | 协调服务 + 目标端 | 定期或泄露后轮换；旧凭证加入撤销列表，目标端拒绝使用已撤销凭证 |
| 撤销 | 协调服务 | 撤销列表（CRL）下发 + 短期 OCSP 风格查询；目标端本地缓存撤销状态 |
| 销毁 | 卸载流程 | 卸载时清除本地凭证，防止残留身份被复用 |

### 2.2 设备身份构成

设备身份不依赖单一可伪造属性，而是绑定组合：

| 属性 | 用途 | 是否单独可信 |
| --- | --- | --- |
| 设备唯一标识（UUID，签发时生成） | 主键 | 否，需配合凭证 |
| 设备证书（协调服务签名） | 身份证明 | 是，但需验证撤销状态 |
| 设备私钥（本地保护） | 证明持有 | 是，但需防提取 |
| 硬件指纹（可选辅助） | 辅助绑定物理设备 | 否，仅辅助 |

**不以主机名、MAC 地址或 IP 地址单独作为身份凭据**（PA-R02）。这些属性仅作为辅助显示和连接寻址，不参与授权判定。

### 2.3 协调服务失陷后的处置

| 失陷场景 | 处置 |
| --- | --- |
| 协调服务私钥泄露 | 管理员轮换服务根密钥；所有设备证书重新签发；旧证书全局失效 |
| 撤销列表被篡改 | 目标端使用短时缓存 + 强制周期刷新；缓存过期后默认拒绝新会话（fail-closed） |
| 协调服务被冒充 | 设备预置服务证书指纹；连接时双向验证，不信任未知服务证书 |
| 协调服务离线 | 见 §4 撤权传播与失联行为 |

**关键原则：fail-closed。** 协调服务不可用时，目标端不默认放行新会话，仅允许已建立的会话按本地缓存的撤销状态继续至超时或主动结束。

## 3. 点对点安全协议（对应 DG-04）

### 3.1 双向认证与通道建立

```
发起端                         协调服务                        目标端
  │                              │                              │
  │── 1. 会话申请(目标ID) ──────→│                              │
  │                              │── 2. 策略判定 ──→ (授权/拒绝)  │
  │←─ 3. 会话凭证(短期) ─────────│                              │
  │                              │── 4. 通知目标: 会话已授权 ───→│
  │                              │   (含会话ID/发起端身份/范围/有效期)│
  │←────── 5. 目标端寻址信息 ─────│                              │
  │                              │                              │
  │══════════════ 6. 点对点双向认证 + 加密通道建立 ══════════════│
  │   (互相验证会话凭证 + 设备证书，建立 TLS/自定义加密通道)        │
  │══════════════ 7. 媒体/控制数据加密传输 ══════════════════════│
```

### 3.2 通道安全要求

| 要求 | 实现 |
| --- | --- |
| 双向认证 | 发起端与目标端互相验证对方设备证书 + 会话凭证签名 |
| 加密 | 强制加密所有媒体与控制数据（TLS 1.3 或等效） |
| 抗重放 | 每会话单调序列号 + 时间戳窗口校验 |
| 会话绑定 | 会话凭证绑定（操作者, 目标设备, 会话ID, 允许操作类型, 有效期） |
| 前向安全 | 通道密钥协商使用临时密钥，会话结束后不可恢复 |
| 防劫持 | 会话凭证单次使用，建立后即失效；通道绑定会话ID，不接受替换 |

### 3.3 目标端独立验证（关键）

**目标端不盲信协调服务的"已授权"通知**，而是独立验证：

| 验证项 | 验证方式 |
| --- | --- |
| 会话凭证签名 | 用预置协调服务公钥验证凭证签名 |
| 凭证有效期 | 本地时钟校验，拒绝过期凭证 |
| 撤销状态 | 查询本地撤销缓存 + 必要时向协调服务查询 |
| 发起端身份 | 验证发起端设备证书与凭证中绑定身份一致 |
| 授权范围 | 校验凭证中允许的操作类型与实际请求一致（查看/投送/控制） |
| 会话唯一性 | 拒绝重复会话ID，防止重放 |

若任一验证失败，目标端拒绝建立通道并记录审计事件。

## 4. 撤权传播与失联行为（对应补充项 2）

### 4.1 撤权传播机制

| 机制 | 说明 |
| --- | --- |
| 即时推送 | 协调服务向目标端推送撤权通知，目标端立即终止会话并停止接受输入 |
| 撤销列表刷新 | 目标端周期刷新撤销缓存；缓存中标记为撤销的会话立即终止 |
| 凭证短时有效 | 会话凭证有效期短（如 5–15 分钟），超时自动失效，需重新授权续期 |
| 续期重新验证 | 续期必须重新通过协调服务策略判定，不自动延长 |

### 4.2 失联行为矩阵

| 场景 | 目标端行为 | 发起端行为 | 现有会话 |
| --- | --- | --- | --- |
| 协调服务不可用（新会话申请） | — | 拒绝（无法获取凭证） | 不建立 |
| 协调服务不可用（会话进行中） | 按本地撤销缓存继续至凭证超时 | 继续至凭证超时 | 继续至超时后终止 |
| 撤权消息未送达 | 撤销列表刷新时发现撤权 → 终止 | 通道心跳超时或撤销列表同步后终止 | 终止（依赖列表刷新 + 凭证超时兜底） |
| 目标端重启 | 清除所有会话状态 | 连接断开，需重新申请 | 终止 |
| 发起端重启 | 通道断开 | 需重新申请会话 | 终止 |
| 网络分区（两端断连） | 心跳超时 → 停止接受新输入 | 心跳超时 → 标记断线 | 终止，恢复后需重新认证 |
| 凭证超时 | 拒绝续期请求外的所有操作 | 需重新申请 | 终止 |

**关键原则：不依赖客户端主动配合终止。** 目标端通过凭证超时 + 撤销列表刷新 + 心跳超时三重机制独立判定会话失效，即使发起端不配合，会话也会在凭证有效期内终止。

### 4.3 心跳与超时参数（初始，P0 校准）

| 参数 | 初始值 | 说明 |
| --- | --- | --- |
| 心跳间隔 | 2 s | 检测通道活性 |
| 断线判定 | 3 次心跳未响应（6 s） | 判定连接断开 |
| 会话凭证有效期 | 10 min | 超时自动失效 |
| 撤销列表刷新间隔 | 30 s | 目标端主动刷新 |
| 撤销缓存过期 | 5 min | 过期后 fail-closed，拒绝新会话 |

## 5. 权限分离细化（对应补充项 3）

### 5.1 权限分类

| 权限类 | 持有者 | 范围 | 禁止 |
| --- | --- | --- | --- |
| 设备身份与凭证 | 后台服务（Session 0） | 凭证存储、身份证明、撤销查询 | 交互客户端不可直接访问私钥 |
| 策略与授权判定 | 协调服务 | 签发会话凭证、策略计算 | 不直接操作目标桌面 |
| 屏幕采集 | 交互客户端（用户会话） | 当前用户桌面 Graphics Capture | 采集授权会话外内容 |
| 远程输入注入 | 交互客户端（用户会话） | 当前用户桌面鼠标键盘 | 跨会话、安全桌面、提权 |
| 媒体传输 | 交互客户端 | 加密发送/接收屏幕帧 | 后台服务不转发媒体 |
| 状态提示 | 交互客户端 | 用户桌面可见 UI | 不可被远程输入静默关闭 |

### 5.2 后台服务能力边界（明确禁止）

后台服务**不得**成为以下通用代理：

- ❌ 任意进程操作（创建/终止/读写任意进程内存）。
- ❌ 任意输入注入（不通过交互客户端直接注入鼠标键盘）。
- ❌ 跨用户会话访问（不访问非当前活动会话的桌面）。
- ❌ 任意文件系统操作（仅限自身凭证存储与日志）。
- ❌ 直接采集或编码屏幕（由交互客户端负责）。

后台服务仅负责：设备身份、凭证管理、本地 IPC 认证端点、撤销状态查询、审计记录。

### 5.3 交互客户端能力边界

| 能力 | 条件 |
| --- | --- |
| 屏幕采集 | 仅当持有有效授权会话且采集范围绑定该会话 |
| 输入注入 | 仅当会话凭证包含控制权限（非仅投送/查看） |
| 状态显示 | 始终，不可关闭 |
| 凭证访问 | 不可，仅通过 IPC 请求服务代为身份操作 |

### 5.4 本地 IPC 调用白名单

| 调用 | 调用方 | 允许 |
| --- | --- | --- |
| 请求会话身份证明 | 交互客户端 → 服务 | ✓ |
| 查询撤销状态 | 交互客户端 → 服务 | ✓ |
| 写审计事件 | 交互客户端 → 服务 | ✓ |
| 读取设备私钥 | 交互客户端 → 服务 | ✗ |
| 任意进程操作 | 交互客户端 → 服务 | ✗ |
| 任意文件操作 | 交互客户端 → 服务 | ✗ |

IPC 双向认证：服务验证客户端属于当前授权会话的交互进程；客户端验证服务为预置指纹的本地服务。
