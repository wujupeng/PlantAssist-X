# Windows 会话模型 — 权限分离设计

> 状态：P0 必须验证 · 待实测

## 1. 问题背景

Windows 采用多会话架构：

- **Session 0**：服务进程运行于此，无交互桌面，无法直接访问用户界面的 GDI/Direct3D 资源。
- **Session 1+**：交互式用户会话，每个登录用户拥有独立的桌面、窗口站和剪贴板。

PlantAssist-X 需要在用户桌面进行屏幕采集与输入注入，但设备身份、授权和连接生命周期管理属于系统级职责。两者必须分离。

## 2. 权限分离方案

```
┌──────────────────────────────────────────────┐
│  Session 0（后台服务，低特权）                  │
│  ├─ Device Identity / Credential Store       │
│  ├─ Policy Engine / Session Broker           │
│  ├─ Audit Service                            │
│  └─ Local IPC Server（认证后端点）             │
└──────────────────────────────────────────────┘
                  │  本地 IPC（认证 + 最小调用集）
                  ▼
┌──────────────────────────────────────────────┐
│  Session N（交互式用户会话，当前登录用户）       │
│  ├─ Screen Capture（Graphics Capture API）   │
│  ├─ Media Encoder / Transport               │
│  ├─ Input Gateway（鼠标键盘注入，受授权约束）   │
│  ├─ Target UI（会话状态提示，不可静默隐藏）     │
│  └─ Local IPC Client                        │
└──────────────────────────────────────────────┘
```

## 3. 设计约束

| 约束 | 说明 |
| --- | --- |
| 不注入进程 | 不向其他进程注入代码以获取其桌面访问权。 |
| 不复制凭据 | 不复制或重放用户登录凭据跨会话操作。 |
| 不绕过安全桌面 | UAC 提权、Winlogon 界面属于安全桌面，明确列入不支持清单。 |
| IPC 认证 | 服务与用户进程通信必须双向认证，限制可调用操作白名单。 |
| 状态可见 | 交互式客户端必须在用户桌面持续显示会话状态。 |

## 4. P0 必须实测的会话场景

| 场景 | 验证目标 | 预期结果 |
| --- | --- | --- |
| 用户已登录 | 正常桌面采集与显示 | 支持 |
| 锁屏 | 采集行为与状态提示 | 明确行为边界 |
| 解锁 | 会话恢复 | 支持 |
| 切换用户 | 多会话并存时的目标选择 | 明确选择规则 |
| UAC 弹窗 | 安全桌面采集 | 不支持，明确提示 |
| 用户注销 | 会话清理与权限回收 | 立即终止会话 |
| 服务重启 | 连接恢复与重新认证 | 不残留控制权限 |
| 网络中断 | 断线检测与清理 | 停止接受新输入 |

## 5. 不支持清单（初始）

- UAC 安全桌面（提权弹窗）的远程查看与输入。
- Winlogon 登录界面的远程操作。
- 跨用户会话同时操作多个桌面（首期仅支持当前活动会话）。
- 通过服务进程直接操作用户桌面 GDI 资源。
