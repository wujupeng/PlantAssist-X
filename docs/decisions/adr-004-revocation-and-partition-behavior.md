# ADR-004：撤权传播与失联行为

> 状态：已提出 · Gate B 补充 · 2026-10-28

## 背景

补充项 2 要求明确协调服务不可用、撤权消息未送达、设备重启和网络分区时，现有会话如何停止或失效，不能仅依赖客户端主动配合。

## 决策

### 三重失效兜底（不依赖客户端配合）

1. **即时推送**：协调服务向目标端推送撤权通知，立即终止。
2. **撤销列表刷新**：目标端周期刷新（30 s），发现撤权即终止。
3. **凭证超时**：会话凭证短时有效（10 min），超时自动失效。

即使撤权推送未送达，撤销列表刷新会在 30 s 内兜底；即使列表刷新失败，凭证超时在 10 min 内兜底。

### 失联行为

- 协调服务离线 + 新会话 → 拒绝建立。
- 协调服务离线 + 会话进行中 → 按本地缓存继续至凭证超时。
- 网络分区 → 心跳超时（6 s）判定断开，停止接受新输入，恢复后需重新认证。
- 设备重启 → 清除所有会话状态，需重新申请。

### fail-closed

撤销缓存过期（5 min）后，目标端拒绝新会话，不默认放行。

## 后果

- 撤权最大延迟 ≈ 撤销列表刷新间隔（30 s），最坏 ≈ 凭证有效期（10 min）。
- 协调服务离线时新会话不可建立（可接受折损）。
- 需要心跳机制与超时参数（P0 校准）。
